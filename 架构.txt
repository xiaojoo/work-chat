```sql
CREATE TABLE chat_friend (

    status TINYINT DEFAULT 1,
    create_time DATETIME NOT NULL,
    PRIMARY KEY (id),
```

# 八、会话设计

这个非常重要。

不要把：

```text
好友
群
消息
```

混在一起。

建立：

```text
conversation
```

概念。

例如：

```text
A 和 B
↓
conversationId = c10001
```

群：

```text
群 10001
↓
conversationId = g10001
```

# 十一、WebSocket 消息协议

一定要在项目早期就把协议定义好。

客户端发送：

```json

    "content": "你好"
```

服务器返回：

```json

  "type": "MESSAGE_ACK",
  "requestId": "req-10001",
  "data": {
    "messageId": "msg-10001",

```

然后：

```json

  "type": "MESSAGE_RECEIVE",
  "data": {
    "messageId": "msg-10001",
    "conversationId": "10001",
    "senderId": 10001,
    "messageType": "TEXT",
    "content": "你好",
    "serverTime": 1750000000000
  }
}
```

# 十四、Connection Manager


# 十五、WebSocket 心跳

必须实现：

```text
客户端
   │
   │ PING
   ▼
服务器
   │
   │ PONG
   ▼
客户端
```

例如：

```text

```

发送一次心跳。

如果：

```text
连续 3 次
没有响应
```

否则很容易出现：

> 用户已经断网，但服务器还认为他在线。

# 十八、为什么消息不能只经过 Redis？

例如：

```text
A → Redis → B
```

看起来简单。

但是：

```text
Redis
```

不应该承担完整的消息持久化职责。

因为你需要：

```text
消息历史
消息可靠性
消息查询
消息分页
消息重放
消息审计
```

所以：

```text
Redis
=
实时状态

Cassandra
=
消息历史
```

这个职责一定要分开。

# 十九、Cassandra 表设计

可以先：

```sql
CREATE TABLE messages (
    conversation_id text,
    message_date date,
    message_id timeuuid,
    sender_id bigint,
    message_type text,
    content text,
    create_time timestamp,
    PRIMARY KEY (
        (conversation_id, message_date),
        message_id
    )
) WITH CLUSTERING ORDER BY (
    message_id DESC
);
```

为什么加：

```text
message_date
```

？

因为一个超大群：

```text
conversation = 10001
```

可能产生几十亿条消息。

不能让一个 Partition 无限增长。

所以可以按照：

```text
conversation
+
day
```

分区。

例如：

```text
群10001
2026-08-24

群10001
2026-08-25
```

# 二十五、WebSocket 状态机

前端应该有：

```text
DISCONNECTED
      ↓
CONNECTING
      ↓
CONNECTED
      ↓
DISCONNECTING
      ↓
DISCONNECTED
      ↓
RECONNECTING
```

自动重连：

```text

2 秒
4 秒
8 秒
16 秒
```

最大：


```text
10000 个客户端
同时疯狂重连
```

把服务器再次冲垮。
